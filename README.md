# SSN Community Treasury

Existing React treasury app with the requested Excel workbook as its temporary database. Member and Admin credentials are authenticated by the local API; passwords are stored directly in the Owner Details worksheet. The session-signing secret remains configured on the API server.

## Local setup

Requires Node.js 18 or newer.

1. Install packages: `npm.cmd install`.
2. Copy `.env.example` to `.env.local`. Set `AUTH_SECRET` to a random secret of at least 32 characters. Keep `.env.local` private.
3. Create the empty three-sheet workbook: `npm.cmd run workbook:init`. It is created at `data/ssn_treasury.xlsx` by default; set `EXCEL_DB_PATH` to choose another local file.
4. In one terminal run `npm.cmd run server` to start the authenticated API on `127.0.0.1:8787`.
5. In another terminal run `npm.cmd run dev` and open the Vite URL. Vite proxies `/api` requests to the local API.

For a production build, run `npm.cmd run build`, then `npm.cmd run server`; the Node server serves `dist/` and `/api` from the same origin. Local workbook storage is the default; configure Google Drive storage below to use Drive as the canonical workbook.

### Google Drive storage

The app can use an existing `.xlsx` in Google Drive as its canonical workbook. Create a Google Cloud service account, enable the Google Drive API, and download its JSON key outside the repository. Share the workbook with the service account email as an Editor. Set `GOOGLE_DRIVE_FILE_ID` to the workbook ID from its Drive URL and `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` to the local JSON key path. The service account key must remain private and must not be committed.

When Drive settings are present, the API downloads the workbook before reads and writes changes back to that same Drive file. `EXCEL_DB_PATH` is a local working copy. Payment evidence is compressed and stored as Base64 in the workbook; expense attachments remain local files. Leave the Google Drive settings blank to use local workbook and attachment storage.

## Workbook

The initializer creates exactly these worksheets with the requested column order:

- `Owner Details`: Owner ID, User Name, Password (plaintext), Name, Mobile Number, Email, Phase, Plot Number, Address, Secondary Mobile Number, Secondary Email, Created Date, Created By, Role.
- `Expense Details`: Expense ID, Title, Description, Comment, Amount, Approved By, Requested By, Status, Attachment Name, Attachment File, Expense Type.
- `Maintenance Payment Details`: Owner ID, Owner Name, Title, Quarter, Plot Number, Phase Number, Payment Amount, Status, Created Date, Created By.

Status options are enforced by the API. Expense rejection is represented in the existing schema by keeping `Status` as `Pending` and recording `Rejected by: ...` in `Approved By`; the app displays the derived status as Rejected. Expense records have no date column, so the dashboard shows all expense rows rather than claiming a date-based expense total.

The Owner form validates a unique 3–32 character username, a password of at least 12 characters, and required contact, phase, and plot data. New Owner accounts are assigned the Member role. On first startup, the API bootstraps the configured Admin into Owner Details and stores the password directly; after that, Admin sign-in is verified against the workbook. The Admin row is listed as read-only in Owner Details and is excluded from owner counts and owner financial operations. Expense Type is required and limited to Phase 1 Park, Phase 2 Park, Road, Phase 3 Park, Mandabam, EB Work, or Security Payment. Owner IDs (`OWN-00001`...) and Expense IDs (`EXP-00001`...) are generated by the API. Duplicate usernames, mobile numbers, phase/plot pairs, invalid statuses, and duplicate owner-quarter-year maintenance records are rejected or skipped. Quarterly maintenance is ₹1,500 per house; Admins select a phase, then a user from that phase, to create one Pending record. The selected user’s plot is shown from Owner Details, and duplicate records for that user, quarter, and financial year are skipped. Owners see their own pending and completed maintenance records in My Maintenance. Existing workbooks are upgraded by adding the Username, Password, and Role columns without dropping Owner rows. Existing records default to Member. The Password cells contain the entered password directly. Imported Owners without passwords cannot sign in until an Admin sets one in their Owner Details form.

Run `npm.cmd run seed:test-data` to add one fictional `TEST DATA ONLY` record to each sheet. The command is idempotent; remove those rows before entering production records.

## Authentication and roles

Members and Admins sign in with the username and password stored in Owner Details. Admin credentials come directly from Owner Details rows whose Role is `Admin`; no `.env` credentials are used. The API compares passwords directly with the workbook Password column, signs eight-hour sessions with `AUTH_SECRET`, and verifies those sessions for every protected API request. Owners can submit or edit payment date, method, reference, and image evidence for pending maintenance records; submission changes the status to `Pending Approval` for Admin review. Evidence is limited to JPEG, PNG, or WebP images up to 4 MB and is served only to the linked Owner and Admin. Password recovery is not self-service.

Expense requests and their history are visible only to Admins; Owners may submit requests with an optional PDF or image attachment (up to 10 MB), but their API responses and dashboard do not include expense records. Attachment files are stored outside Excel and are viewable only by Admins. Admins can manage Owners, review expenses, generate maintenance records, update statuses, and delete records from the record lists and Overview activity. Deleting an Owner or Expense also deletes linked attachment files after confirmation. The Owner directory is read-only for Owner accounts and shows only names, phases, and plot numbers; Admins retain the full directory. The API takes the Owner ID from the verified signed session, not from the request body.

## Deployment

This application requires a Node-capable host because it serves both React and authenticated `/api` routes.

Set these production environment variables:

- `PORT` (provided automatically by many hosts)
- `AUTH_SECRET` (random secret of at least 32 characters)
- `GOOGLE_DRIVE_FILE_ID=1iwqvRKCTQZY2u0yC7ZRjOPFnImN6mRGS`
- `GOOGLE_SERVICE_ACCOUNT_KEY_JSON` (full JSON key contents) or `GOOGLE_SERVICE_ACCOUNT_KEY_FILE`
- `VITE_API_URL=/api`
- `VITE_CURRENCY=INR`
- `VITE_DATABASE_GOOGLE_SHEET_URL=https://docs.google.com/spreadsheets/d/1iwqvRKCTQZY2u0yC7ZRjOPFnImN6mRGS/edit`

Build and start:

```bash
npm run build
npm start
```

For a Docker host:

```bash
docker build -t ssn-treasury .
docker run --env-file .env.production -p 8787:8787 ssn-treasury
```

Configure `onlinecomparer.com` DNS with an `A` record to the host IP or a `CNAME` to the provider hostname, then enable HTTPS through the host reverse proxy or CDN. Attachments should use persistent storage or object storage for restarts and multiple instances.

### GoDaddy deployment

GoDaddy shared/basic Web Hosting plans normally only serve static PHP/HTML files and cannot keep this Node API process running. Use one of these GoDaddy options:

- GoDaddy VPS or Dedicated Server: deploy this Docker container or Node application, then configure a reverse proxy for port 8787 and attach HTTPS.
- GoDaddy Hosting with cPanel's "Setup Node.js App": set application root to the project directory, startup file to `server/index.js`, Node version 22, and application URL/subdomain to `onlinecomparer.com`. Configure environment variables in cPanel, run `npm ci`, run `npm run build`, and start/restart the app. cPanel must expose the app over HTTPS and route `/api` to the Node process.
- Static-only GoDaddy plan: use a separate Node host (Azure App Service, Render, or DigitalOcean) for the API and point `onlinecomparer.com` to the static app via CDN/forwarding. This is not directly deployable without changing the frontend/API architecture.

After deployment, add DNS in GoDaddy:

- Root domain: `A` record pointing to the VPS or hosting provider IP.
- `www`: `CNAME` to `onlinecomparer.com` or the provider hostname.
- Enable SSL in GoDaddy or the provider control panel.

Do not upload `.env.local`, the service-account JSON, or `dist` secrets to public folders. Set the production environment variables through GoDaddy's server/cPanel/hosting control panel.

## Data layer

`server/excelRepository.js` owns workbook parsing, validation, IDs, reporting data, and updates. API routes call this repository instead of reading Excel directly. Each request is serialized in the local server process, then the workbook is written to a temporary file and atomically replaced with a recovery backup. Run only one API instance against a workbook. The repository boundary can later be replaced with a Google Sheets implementation without changing React actions or the business layer.

The workbook contains personal contact data. Keep it private in Drive, share it only with the service account and trusted users, back it up securely, and do not commit a populated workbook. Run only one API instance against a workbook. Automated repository checks run with `npm.cmd test`.
